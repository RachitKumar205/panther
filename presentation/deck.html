Problem Formulation

One precision per matrix

A contest is a (model, RAM budget) pair. Find the per-matrix quantization type assignment that fits the budget and loses the least quality.

Genome
g = (g1, …, gM), gi ∈ T
one of 13 quantization types per matrix
Feasibility
0.99·B ≤ RAM ≤ 1.005·B
RAM(g) = file size + KV cache + overhead
Objective
score = flips% + 10·KL
minimize over feasible genomes

A genome assigns one of 13 quantization types to each of the model's matrices: the word table, the seven matrices of every transformer layer, and the output head. With 13 types per matrix, that is 13197 layouts for the 1.5B model and 13338 for the 14B, far too many to enumerate, so we evolve the genome with a genetic algorithm.

Candidates are scored by a single fitness, flips% + 10·KL: answer flips on benchmark questions plus a next-token divergence against the original. Only genomes whose RAM lands inside the window 0.99·B to 1.005·B are kept.

Research Contributions

Four contributions

From formulation to evaluation protocol, each closes a gap left by prior work.

01
Per-matrix formulation
Budget-constrained LLM deployment framed as a search over per-matrix quantization types.
02
Near-free evaluation
GPTQ-compensated type copies assembled by byte copy, so no re-quantizing during search.
03
Unified fidelity metric
flips% + 10·KL scores candidates and ready-made presets on one scale.
04
Honest evaluation protocol
Disjoint data sets, and a paired 95% interval judging the winner against the best preset.
The space is discrete and non-differentiable, yet easy to search: a genetic algorithm seeded with the best presets evolves per-matrix assignments.

Proposed Methodology

The genetic algorithm

A genome of per-matrix types is evolved under the RAM budget: seeded well, crossed over, and stopped on a clean criterion.

Startseed population
  • 22 preset layouts
  • 13 one-type layouts
  • 4 CP-SAT layouts
  • each repaired into the RAM window
Crossoveroperators
  • two-point gene slicing
  • swaps whole layers, neighbours stay together
  • 30% instead mutate 1-3 matrices by ±1-2 types
Fitnessscore
  • score = flips% + 10·KL
  • measured against the 16-bit original
  • one measure for every candidate and the preset
Stopending metric
  • 15 candidates in a row, no new best
  • 30-70 candidates in total
  • reproducible by seed

Proposed Methodology

The verdict

The winner is judged against the best preset once, on held-out data, with a paired 95% interval that yields WIN, TIE, or LOSE.

Winnerselection
  • 3 finalists, scored on the winner set
  • never on the GA set where they emerged
  • lowest score wins; only its file is kept
Relativethe number
  • relative = ours ÷ preset × 100
  • 100 = the preset's damage
  • below 100 = less damage than the preset
Verdict95% interval
  • relative ± 1.96 · SE of the paired difference
  • WIN below 100 · TIE contains 100 · LOSE above
  • SE = √( SEflips² + (10·SEKL)² )
Paired errorhonest uncertainty
  • flips per question, KL per chunk
  • only questions where the two files differ add uncertainty
  • same questions and text, so it is paired

Dataset Description

Four sets that never overlap

Every set is built from pinned sources and never shares a document, prompt, or question.

SetUsed forQuestions
GA the search's fitness MMLU 300 · HellaSwag 200 · ARC 200 · WinoGrande 200
winner choosing the preset and the winner MMLU 1,000 · HellaSwag 800 · ARC 800 · WinoGrande 800
distill importance matrix, GPTQ, distillation none (text only)
verdict the verdict, once MMLU 2,000 · HellaSwag 2,000 · ARC all · WinoGrande all · GSM8K 500

Built from pinned sources: FineWeb-Edu web text, OpenAssistant chat, and benchmark questions. n-gram dedup drops any document containing 12 consecutive words of a question, keeping answers out of the calibration text.

Nothing is trained on the GA, winner, or verdict sets; nothing is chosen with the verdict set.

Discussion

Interpretation and limitations

The win comes from spending saved bits where they matter. A few limitations and open questions remain.

Interpretationwhat the win means
  • Mixed precision spends saved bits where they matter: most matrices drop to 2-3 bits, a few stay at 4.
  • Step-by-step reasoning (GSM8K) recovers the most, the first place uniform quantization fails.
  • Both winners fit their budget with margin and run at usable speed on the Pi 5.
Limitationschallenges and open items
  • Two models run so far (1.5B, 14B); the 7B, 22B, and 24B contests remain.
  • The 14B Pi run was thermally throttled, so its speed is a lower bound.
  • QAT's on-disk cache is large (172 GB for the 14B), so it stays optional.
  • Results aren't directly comparable to the old pipeline; the fair test is both winners through the same verdict.
Panther · CSD36114
Conclusion

Memory becomes a quality win

Mixed-precision search turns a hard memory budget into a quality win over the best ready-made preset.

What we foundkey results
  • Both contests WIN: relative damage 67.1 (1.5B) and 74.1 (14B), intervals below the preset.
  • Models shrink about 80% (16-bit to ~3 bits per weight) and still fit their budgets.
  • Reasoning recovers the most: GSM8K +22.4 points on the 1.5B.
Where this goesfuture work
  • Training-time quantization: fold the QAT objective into the model's own training.
  • Mixture-of-experts: keep rarely-routed experts at extreme low precision.
  • Layer-wise loading: one resident layer, stream the rest (AirLLM).
